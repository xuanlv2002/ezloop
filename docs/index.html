01核心理念

引擎不理解任何具体能力，它只负责流转。

大多数 Agent 框架把重试、MCP、审批、日志焊死在引擎里，能力越多，引擎越重。 ezloop 只保留一个 model ↔ tool 循环引擎，其余一切皆是可插拔的扩展： 模型重试是一个 Warp，MCP 接入是一个 Hook，工具审批是一个 Hook，会话持久化也是一个 Hook。 不用，就不引入。

三个核心概念

概念关注点扩展方式
model 节点本身：模型调用 实现 provider.ModelProvider + WithModelWarp 中间件（warp.ModelHandler）
tool 节点本身：工具执行 实现 types.Tool + WithToolWarp 中间件（warp.ToolHandler）
hook 流的前后：生命周期与控制流 实现 hook 小接口 + WithHooks 插入

三条设计原则

1
节点与流分离
model / tool 是循环的节点，用 Warp 装饰 —— 管「怎么执行」； hook 是循环的切面，按时机插入 —— 管「什么时候做什么」。两者互不越界。
2
扩展永不入核
框架层零扩展依赖。官方 SDK、重试策略、审批逻辑全部收敛在 ext/ 层， 按需引入，引擎永远保持最小。
3
状态即消息
loop 的全部状态是 LoopState，其中 Messages 可序列化、 可恢复、可直接作为下一轮历史。没有隐藏的内存中间态。

Event 与 Hook 分离

OnEvent 回调实时观察（含流式 chunk），只读不写； 修改状态是 Hook 的职责。emit 的入口按层对称：hook（横向切面）拿 state， 走 state.EmitEvent("ns.type", data)；warp（纵向装饰）在每次 Run 组装时由引擎注入 event.Emitter（观察面的最小暴露，不碰 state）， 两层事件汇入同一个流（如 modelretry.retry）。

并发契约：工具天然并发执行，OnEvent 回调可能被多个 goroutine 同时调用 （engine 自身事件仍串行且保序）——回调必须并发安全且快速返回； 需要免锁消费时用 RunAsync 的 Events 通道。

KV cache 友好：工具定义与 system 前缀属于 prompt 缓存前缀。mcpRouter 的 schema 恒定、 WithHistory 自动过滤历史中的 system 消息 —— 每轮对话的前缀稳定，不击穿缓存。

02Loop 引擎

一次 Run 的完整生命周期：注入 → 循环 → 收尾。

执行流程

  1. 初始化：构造 LoopState（system prompt → 历史 → 本轮输入）， 依次执行 startHook —— 这是注入工具（mcp router）与技能的时机。
  2. 循环（≤ MaxIterations）： modelStartHook → 调用模型（流式时 chunk 实时成事件）→ modelEndHook → 响应含 tool calls 则执行工具后回到模型；不含则循环结束。
  3. 收尾：endHook 无论成败都执行（defer 语义）—— 摘要、会话快照、连接清理都在这里。

七个 Hook 的作用点

#接口作用点典型用途
1StartHookloop 开始注入工具、技能指令
2ModelStartHook调用模型前预算守卫（置 Stop 提前终止）
3ModelEndHook模型响应后响应改写、审计
4ToolStartHook工具调用前审批 / 人机中断（Skip(result) / Abort 短路，可阻塞等决策）
5ToolEndHook工具调用后（结果入史前）审计日志、结果后处理（offload 卸载）
6LoopHook迭代回边前上下文压缩、配置热加载
7EndHookloop 结束摘要、资源清理、会话保存
budget_hook.go — 一个插件只写业务，健壮性由引擎兜底
type BudgetHook struct{ Remaining int }

func (h *BudgetHook) Name() string { return "budget" }
func (h *BudgetHook) OnModelStart(_ context.Context, s *types.LoopState) error {
    if s.Iteration > h.Remaining {
        s.Stop = true // 提前终止，EndHook 仍会执行
    }
    return nil
}

agent := core.NewAgent(p, core.WithHooks(&BudgetHook{Remaining: 10}))

工具执行：三阶段模型

  • 判定 —— toolStartHook 按调用并发执行 （单调用内 hooks 仍串行）：多个人工审批同时呈现给用户，而不是排队逐个等。 返回 hook.Skip(result) 跳过该调用（result 作为工具结果写入历史）， hook.Abort 终止整个 loop（联动取消其余判定）。 hook 可以阻塞等待人工决策（审批、ask_user、规划确认都建立在这上面），引擎对「等待」零感知。
  • 执行 —— 每个调用是独立单元（判定 → warp 壳内执行 → toolEnd 后处理整链跟调用走）， 默认全部并发（调用数即并发数，不可配；SerialTools 可选串行；限流在 tool warp 内实现）， 每个调用独立 panic 恢复，工具错误不终止 loop。
  • 收尾 —— 结果消息、toolEndHook、事件严格按调用顺序发出，并发但不乱序。

健壮性语义（引擎内置）

  • 工具错误回传模型自纠 —— 只有 hook 报错或 hook.Abort 才终止 loop；
  • 历史永不断裂 —— 无论完成、Skip、Abort、hook 报错还是取消， 每个 tool_call 都有对应结果消息：发给模型的序列永远协议完整，持久化恢复无需理解断点 （进入引擎前的历史由 contextfix 兜底）；
  • Hook 标准防护 —— 任意 hook panic 被恢复为带 hook 名与阶段的 error，单个扩展崩溃不会炸掉 loop；
  • ctx 取消 —— 循环顶部与模型调用检查 ctx.Err()，归类为 cancelled 而非 error；
  • EndHook 保证执行 —— defer 语义，成败皆跑。

双轨 API：同步与异步

run.go
// 同步：单轮 + 实时回调
state, err := agent.Run(ctx, "帮我读一下 hello.txt")

// 多轮：上一轮的 Messages 直接作为历史（system 自动去重）
state, err = agent.Run(ctx, "再总结一下", core.WithHistory(state.Messages...))

// 异步：事件通道 + 取消（服务端场景，与 WithOnEvent 二选一）
h := agent.RunAsync(ctx, "长任务")
defer h.Cancel()                     // 幂等
for e := range h.Events() { render(e) }  // loop 结束自动 close
state, err = h.Wait()

RunAsync 的事件通道缓冲 256、满时阻塞 loop（不丢事件）； Cancel() 幂等，取消后 state 归类 cancelled。

04第一个 Agent

十行代码跑起来 —— OpenAI 兼容接口（DeepSeek / SiliconFlow / vLLM / Ollama 通用）。

main.go
package main

import (
    "context"
    "fmt"
    "os"

    "github.com/xuanlv2002/ezloop/core"
    "github.com/xuanlv2002/ezloop/ext/provider/openai"
)

func main() {
    p := openai.New(openai.Options{
        BaseURL: os.Getenv("OPENAI_BASE_URL"),
        APIKey:  os.Getenv("OPENAI_API_KEY"),
        Model:   "deepseek-ai/DeepSeek-V3.2",
    })
    agent := core.NewAgent(p, core.WithSystemPrompt("你是一个严谨的助手"))

    state, err := agent.Run(context.Background(), "用一句话介绍 loop 引擎")
    if err != nil {
        panic(err)
    }
    fmt.Println(state.Messages[len(state.Messages)-1].Content)
}

05官方扩展指南

所有能力都在 ext/ 层，按需引入 —— 不用不依赖。

底座

ext/fs 底座

FileSystem 核心接口（Read / Write / List）+ 两个可选能力接口： Modifier（Edit / ApplyPatch 原子补丁）、Searcher（Grep / Find）。 Local 实现全部能力，带 root 沙箱（路径穿越被拒绝）与补丁预检 + 回滚。

fs.go
fsys := fs.NewLocal(".")              // 沙箱 = 当前目录
data, _  := fsys.Read(ctx, "a.txt")
_        = fsys.Write(ctx, "b.txt", []byte("hi"))
entries, _ := fsys.List(ctx, ".")

// 能力探测：filetools 等下游按实现注册工具
if m, ok := fsys.(fs.Modifier); ok  { m.Edit(ctx, "a.txt", "old", "new") }
if s, ok := fsys.(fs.Searcher); ok { s.Grep(ctx, fs.GrepRequest{Pattern: "TODO"}) }

model 节点

ext/provider/openai model

OpenAI 兼容 Provider：Invoke + SSE 流式（tool call 增量聚合、usage 统计）， 兼容 DeepSeek / SiliconFlow / vLLM / Ollama。

provider.go
p := openai.New(openai.Options{
    BaseURL: "https://api.siliconflow.cn/v1",
    APIKey:  "sk-xxx",
    Model:   "deepseek-ai/DeepSeek-V3.2",
    Headers: map[string]string{"X-Custom": "v"},  // 可选
})
// 同时实现 Invoke 与 Stream：WithStreaming(true) 时自动走流式

Warp：节点装饰器

ext/warp/model/modelretry warp

模型重试：指数退避 + 抖动；流式仅在尚未发出 chunk 时重试（已发出的内容不可撤回）。 每次重试发出 modelretry.retry 事件（含尝试序号、失败原因、退避时长）， 经引擎事件流到达 OnEvent / RunAsync，前端可渲染「第 N 次失败，Xms 后重试」。 默认只重试可重试错误（openai.HTTPError 的 408/429/5xx、未知错误保守重试、取消不重试）， Options.RetryIf 可按错误信息任意自定义。

retry.go
agent := core.NewAgent(p, core.WithModelWarp(modelretry.Warp()))
// 自定义可重试判定：
core.WithModelWarp(modelretry.Warp(func(o *modelretry.Options) {
    o.RetryIf = func(err error) bool { return !strings.Contains(err.Error(), "quota") }
}))
// 降级 / 多模型路由？自己写一个 warp.ModelHandler：func(ModelProvider) ModelProvider

ext/warp/tool/safetool warp

工具防护：panic 恢复为 error（附工具名），工具错误附加上下文 —— 单个工具崩溃不炸 loop。

safe.go
core.WithToolWarp(safetool.Warp())
// Warp 挂载在 ToolRegistry 上：静态注册与 hook 运行时注入的工具都会被包装

Hook：流程插件

ext/hook/mcp hook

MCP 接入：mcpRouter 单工具封装。模型只看到一个 schema 恒定的 mcp_router 工具 —— KV cache 友好、server 列表热加载、ACL / OAuth 内聚在 router 内部，模型通过 action: list_tools 自发现工具。内置官方 go-sdk。

mcp.go
cfg := mcp.Config{
    Servers: []mcp.ServerConfig{{
        Name:    "fs",
        Factory: mcp.StreamableHTTP("https://mcp.example.com",
            map[string]string{"Authorization": "Bearer xxx"}),
        // Allow: []string{"read_*"},  // 可选 ACL 白名单
    }},
}
agent := core.NewAgent(p, core.WithHooks(mcp.NewHook(cfg)))
// 模型调用 mcp_router：action=list_tools 发现 → action=call_tool 执行

ext/hook/skill hook

技能注入：代码定义，或从 FS 目录加载 *.md（可选同名 .keywords 文件）； 按输入关键词匹配，命中才注入对应 system 指令。

skill.go
// 方式一：代码定义
h := skill.New(skill.Skill{
    Name: "sql", Description: "SQL 书写规范",
    Keywords:     []string{"sql", "查询"},
    Instructions: "所有查询必须带 LIMIT ...",
})

// 方式二：目录加载 skills/*.md + skills/foo.keywords
h, err := skill.NewFromFS(ctx, fsys, "skills")

agent := core.NewAgent(p, core.WithHooks(h))

ext/hook/approve hook

工具审批：OnToolStart 发出 approve.request 事件后阻塞， 直到使用方经 Decisions channel 送回决策 —— 中断 = goroutine 阻塞，恢复 = channel 来数据。 拒绝理由经 hook.Skip("denied: ...") 成为工具结果进入历史，模型看得见为什么被拒。

approve.go
h, decisions := approve.New(func(c *types.ToolCall) bool {
    if c.Name == "bash" {                    // 参数值级判断：
        var a struct{ Command string `json:"command"` }
        _ = json.Unmarshal(c.Args, &a)
        return !isReadOnly(a.Command)       // 只读命令免审，其余中断等确认
    }
    return c.Name != "read_file"           // false = 免审放行；nil = 全部审批
})
agent := core.NewAgent(p, core.WithHooks(h))

// 决策端：OnEvent 呈现请求，独立 goroutine 送回（同步送回会死锁）
core.WithOnEvent(func(e event.Event) {
    if e.Type != approve.EventRequest { return }
    call := e.Data.(*types.ToolCall)
    go func() {
        decisions <- approve.Decision{CallID: call.ID, Approve: askHuman(call)}
    }()
})
多租户：每会话一套 hook 实例（即一套 channel），事件推给前端，前端按钮回包即送回 channel —— 同一时刻至多一个请求在等（判定段串行），CallID 不匹配的过期决策自动忽略。

ext/hook/askuser hook

ask_user 工具：模型向用户提问，循环中断等待回答，回答原样作为工具结果进入历史。 与 approve 完全同构（事件 + channel），壳工具仅提供 schema 供模型发现。

askuser.go
h, answers := askuser.New()
agent := core.NewAgent(p,
    core.WithHooks(h),
    core.WithTools(askuser.Tool()),  // 注册壳工具供模型发现
)
// OnEvent 收到 askuser.request（Args.question）→
// answers <- askuser.Answer{CallID: call.ID, Input: 用户的回答}

ext/hook/taskplan hook

task_plan 工具：模型提交任务规划后中断等待用户处置 —— Execute（按规划执行）/ Reject（否决）/ Revise（按修改意见调整后重新提交）。处置意见作为工具结果返回， 模型据此继续或修订，修订后重新提交会再次进入等待 —— 天然闭环。

taskplan.go
h, decisions := taskplan.New()
agent := core.NewAgent(p,
    core.WithHooks(h),
    core.WithTools(taskplan.Tool()),  // 模型提交 Args.plan
)
// 用户反馈 →
decisions <- taskplan.Decision{Kind: taskplan.Revise, Input: "加一步压测"}

ext/hook/contextfix hook

历史修理（双向）：Run 开始时（OnStart）给缺失 tool 结果的调用补占位消息、 删除对应 assistant 已丢失的孤儿 tool 消息 —— 引擎保证本轮产生的历史完整，本 hook 保证历史进入引擎前完整 （外部注入的残缺历史、旧版本存档）。完整历史原样返回，零分配。

contextfix.go
core.WithHooks(
    contextfix.New(),  // 建议挂 hooks 首位：历史先修理，后续 hook 再消费
    // ...
)

ext/hook/offload hook

大结果卸载（ToolEndHook）：超过阈值（默认 4KB）的工具结果写入 FS，上下文只留摘要 + 路径； 写失败降级透传。结果后处理不耦合工具节点本身——挂在收尾段改写 result， 故为 hook 而非 warp。

offload.go
core.WithHooks(offload.New(fsys))
// grep 全仓 500 条命中？写进 .ezloop/offload/，模型上下文只留前 512 字节 + 文件路径

ext/hook/filetools hook

文件工具集：按传入 FS 的能力注册 —— read_file（行分页 / 50KB 上限）、write_file、list_dir， + edit_file / apply_patch（需 Modifier）、grep / find（需 Searcher）、bash（需 EnableExec）。 修改类操作走 per-path 队列串行化，防止并发写冲突。建议配 approve。

filetools.go
h := filetools.New(fsys, func(o *filetools.Options) { o.EnableExec = true })
agent := core.NewAgent(p, core.WithHooks(h))
// bash：shell 语义单命令字符串（Windows: cmd /c，Unix: sh -c），支持管道与 &&

ext/hook/summary hook

自动摘要：loop 结束时用模型生成当轮摘要写入 state.Metadata["summary"]； 失败只记 summary_error，永不影响主流程。

summary.go
core.WithHooks(summary.New(p, ""))  // 第二参数：自定义摘要 prompt

ext/hook/localsession hook

会话持久化：每轮 EndHook 滚动快照到 sessions/<id>.json； Load / List 恢复续聊 —— 「状态即消息」的落地。

session.go
session := localsession.New(fsys, "")          // 空 id 自动生成
agent := core.NewAgent(p, core.WithHooks(session))

// 恢复历史会话
s, _ := localsession.Load(ctx, fsys, "", id)
state, _ := agent.Run(ctx, "继续刚才的话题", core.WithHistory(s.Messages...))

var history []types.Message
for {
    fmt.Print("\n你: ")
    if !scanner.Scan() { return }
    input := strings.TrimSpace(scanner.Text())

    // Ctrl+C 只取消当轮：换一个可取消的子 ctx，主循环继续
    turnCtx, cancelTurn := context.WithCancel(ctx)

    state, err := agent.Run(turnCtx, input, core.WithHistory(history...))
    cancelTurn()
    if err != nil { continue }          // 工具错误早已回传模型自纠，这里只剩中止类

    history = state.Messages          // 下一轮直接复用（session 已自动快照）
}

07作为 Web Agent 内核

ezloop 不绑定任何 Web 框架 —— RunAsync + 事件通道就是你的服务端内核。

三个关键映射：

  • 请求 ctx → RunAsync ctx：客户端断开自动取消，state 归类 cancelled；
  • Events 通道 → SSE / WebSocket：loop 结束通道自动 close，range 自然退出；
  • state.Messages → 会话存储：轮次结束 Wait() 拿最终 state， 下轮 WithHistory 带回（或直接用 localsession 落盘）。
server.go — 标准库 SSE，零第三方依赖
func chatHandler(agent *core.Agent, session *localsession.Hook) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        var in struct {
            Input   string `json:"input"`
            Session string `json:"session"`
        }
        _ = json.NewDecoder(r.Body).Decode(&in)

        var history []types.Message
        if in.Session != "" {
            if s, err := localsession.Load(r.Context(), fsys, "", in.Session); err == nil {
                history = s.Messages        // 恢复历史轮次
            }
        }
        session.SetID(in.Session)

        w.Header().Set("Content-Type", "text/event-stream")
        h := agent.RunAsync(r.Context(), in.Input, core.WithHistory(history...))

        for e := range h.Events() {          // loop 结束自动 close
            data, _ := json.Marshal(e)
            fmt.Fprintf(w, "event: %s\ndata: %s\n\n", e.Type, data)
            if f, ok := w.(http.Flusher); ok { f.Flush() }
        }
        state, _ := h.Wait()               // StopReason / Metadata["summary"]
        _ = state
    }
}

http.HandleFunc("/chat", chatHandler(agent, session))
http.ListenAndServe(":8080", nil)
事件即协议：前端按 event.Type 渲染 —— model_chunk 打字机、tool_start 显示工具卡片、 iteration_end 划轮次线、loop_end 收尾。人机交互 hook 的 approve.request / askuser.request 等事件同样会流经这里 —— 前端弹卡片，用户操作回包即送回 channel， 阻塞中的 loop 自然恢复。
注意：同一 Agent 实例可并发服务多个请求（Agent 是只读配置，状态在每次 Run 的 LoopState 里）； 但共享的 session Hook 有 ID 概念，多会话场景建议每请求独立 SetID 或每会话一个实例。
