00简介

ezloop 是一个极简风格的 Golang Agent 框架：核心只有一个 model ↔ tool 循环引擎，其余一切（重试、MCP、审批、技能、文件工具…）都是可插拔的扩展。

概念关注点扩展方式
model节点本身：模型调用实现 provider.ModelProvider + WithModelWarp
tool节点本身：工具执行实现 types.Tool + WithToolWarp
hook流的前后：生命周期与控制流实现 hook 小接口 + WithHooks

一句话：model 和 tool 管节点怎么执行，hook 管流程什么时候插入逻辑。

01安装

要求 Go 1.25+：

go get github.com/xuanlv2002/ezloop

框架层零第三方依赖；接入 MCP 等能力时才会引入对应官方 SDK（都在 ext/ 下，不用不引入）。

02第一个 Agent

三步：创建 Provider → 组装 Agent → Run。

package main

import (
    "context"

    core   "github.com/xuanlv2002/ezloop/core"
    openai "github.com/xuanlv2002/ezloop/ext/provider/openai"
)

func main() {
    p := openai.New(openai.Options{
        BaseURL: "https://api.openai.com/v1", // 可换 DeepSeek / Ollama 等兼容端点
        APIKey:  "sk-xxx",
        Model:   "gpt-4o-mini",
    })

    agent := core.NewAgent(p,
        core.WithSystemPrompt("你是一个严谨的助手"),
    )

    state, err := agent.Run(context.Background(), "你好，介绍一下你自己")
    if err != nil {
        panic(err)
    }
    println(state.LastResponse.Content) // 最终回答
    println(state.StopReason)               // completed
}

Run 内部发生了什么：模型响应若包含 tool calls，引擎自动执行工具并把结果回传模型，循环往复，直到模型给出最终回答、达到 MaxIterations、被 hook 终止或 ctx 取消。

03流式输出

开启 WithStreaming 后，chunk 通过事件实时到达：

agent := core.NewAgent(p,
    core.WithStreaming(true),
    core.WithOnEvent(func(e event.Event) {
        switch e.Type {
        case event.EventModelChunk:
            print(e.Data.(string))      // 增量文本
        case event.EventToolStart:
            // e.Data.(*types.ToolCall)
        }
    }),
)
Event 只做观察（只读），Hook 才能修改状态——两者严格分离。任何 hook 也可以用 state.EmitEvent("my.type", data) 发送自定义事件。

04自定义工具

实现 types.Tool 四个方法即可：

type TimeTool struct{}

func (TimeTool) Name() string        { return "now" }
func (TimeTool) Description() string { return "获取当前本地时间" }
func (TimeTool) ArgsSchema() json.RawMessage {
    return json.RawMessage(`{"type":"object","properties":{}}`)
}
func (TimeTool) Invoke(_ context.Context, _ json.RawMessage) (string, error) {
    return time.Now().Format("2006-01-02 15:04:05"), nil
}

agent := core.NewAgent(p,
    core.WithTools(TimeTool{}),
    core.WithHyperParams(core.HyperParams{
        MaxIterations:  8,
        MaxConcurrency: 4, // 单轮工具并发上限，消息与事件仍保序
    }),
)
工具执行失败或工具不存在不会终止 loop——错误作为结果回传模型供其自纠。同路径并发写冲突可参考 filetools 内置的 per-path 修改队列。

05多轮对话

可恢复状态就是 state.Messages（纯数据，可存库）。下一轮直接作为历史传入：

state1, _ := agent.Run(ctx, "读取 hello.txt")

// 存库 / 传给 UI / 跨进程 …

state2, _ := agent.Run(ctx, "再总结一下",
    core.WithHistory(state1.Messages...))

人机审批也走同一模式：第 1 轮拦截 → 用户批准写入 approve.Store → 第 2 轮携带历史放行，见 examples/approval。

06异步与取消

服务端场景用 RunAsync：事件通道 + 取消 + Wait：

h := agent.RunAsync(ctx, "长任务")
defer h.Cancel()  // 幂等；loop 以 cancelled 停止

for e := range h.Events() { // loop 结束自动 close
    render(e)
}
state, err := h.Wait()

同步模式同样支持取消：Run(ctx, ...) 的 ctx 取消后，引擎在当前节点收尾并以 cancelled 停止，EndHook 保证执行。

07Hook 插件

七个时机的小接口，只实现关心的：

接口时机典型用途
StartHookloop 开始注入工具（mcp router / 文件工具）
ModelStartHook调用模型前预算守卫、提前终止
ModelEndHook模型响应后响应改写
ToolStartHook工具调用前审批拦截（Skip / Abort 短路）
ToolEndHook工具调用后审计日志
LoopHook迭代回边前上下文压缩、配置热加载
EndHookloop 结束连接清理、结果摘要

手写一个预算守卫只需几行，健壮性（panic 恢复、error 上下文）由引擎兜底：

type BudgetHook struct{ Max int }

func (h BudgetHook) Name() string { return "budget" }
func (h BudgetHook) OnModelStart(_ context.Context, s *types.LoopState) error {
    if s.Iteration > h.Max {
        s.Stop = true // 提前终止
    }
    return nil
}

官方插件一行接入：

core.WithHooks(
    skill.New(skill.Skill{Name: "sql", Instructions: "...", Keywords: []string{"db"}}),
    approve.New(approver),                       // 工具审批
    summary.New(smallModel, ""),                  // 结束自动摘要 → Metadata
    filetools.New(fs.NewLocal("./workspace")),     // 文件工具集（root 沙箱）
)

08Warp 中间件

节点维度的装饰器，与 Hook 正交：

core.NewAgent(p,
    core.WithModelWarp(modelretry.Warp()),      // model 节点：指数退避重试
    core.WithToolWarp(
        safetool.Warp(),                        // panic 恢复 + error 上下文
        offload.Warp(fsys),                      // 大结果卸载到文件系统
    ),
)

WithToolWarp 挂载在 ToolRegistry 上：WithTools 静态注册与 hook 运行时注入的工具（如 mcp router）都会被包装。自定义中间件就是一个函数：

func auditWarp(p provider.ModelProvider) provider.ModelProvider { /* 包装 Invoke/Stream */ }

09MCP 接入

模型只看到一个 schema 恒定的 mcp_router 工具（KV cache 友好），server 配置热加载、工具自发现、ACL 收敛在 router 内部：

cfg := mcp.Config{
    Servers: []mcp.ServerConfig{{
        Name:    "fs",
        Allow:   []string{"read"},                // ACL 白名单（可选）
        Factory: mcp.StreamableHTTP("https://mcp.example.com", nil),
        // 或本地进程:  mcp.Stdio("myserver", "--mode=stdio")
    }},
}

agent := core.NewAgent(p, core.WithHooks(mcp.NewHook(cfg)))

模型通过 action=list_tools 自发现工具，再以 action=call_tool 调用；失败返回带 schema 提示的结构化错误供模型自纠。
