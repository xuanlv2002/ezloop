# 最佳实践

上生产前要覆盖的关注点、多租户要点、缓存纪律与测试要求。ezloop 的预期是**每个项目封装自己的 hook / warp**，所以这里的清单按「要解决什么」组织，不绑定任何具体实现（`ext/` 下的官方实现仅作参考，见 README 的说明）。

## 装配前先覆盖这五件事

裸用引擎没有任何内置的重试与防护，以下每一件都值得自己写（或参考 ext/ 的实现抄走）：

| # | 关注点 | 为什么 | 挂在哪 |
| --- | --- | --- | --- |
| 1 | **模型重试** | 429 / 5xx 是常态；流式要只在未发出 chunk 时重试（发过就重放不了） | ModelWarp |
| 2 | **panic 防护 + 并发闸** | 单个工具崩溃不炸循环；一轮 fan-out 不打挂外部资源。防护要包在限流外层 | ToolWarp ×2 |
| 3 | **大结果卸载** | 单次工具输出可能几十 KB 起步，不卸载会撑爆上下文 | ToolEndHook（改写结果为「摘要 + 文件路径」） |
| 4 | **历史修理** | 只要从盘上恢复历史就需要：补缺失 tool 结果、删孤儿 tool 消息 | StartHook |
| 5 | **会话持久化** | EndHook 落盘 + `WithHistory` 恢复，见 [Hook](Hook.md) 的范例三 | EndHook |

一个最小装配的样子：

```go
agent := core.NewAgent(p,
    core.WithSystemPrompt("…"),
    core.WithModelWarp(retryWarp()),          // 你自己的，或抄 ext/modelretry
    core.WithToolWarp(guardWarp(), limitWarp(4)),
    core.WithHooks(historyFix{}, offloadBig{}, sessionSaver{path}),
    core.WithLoopParams(core.LoopParams{MaxIterations: 12}),
)
```

## 自封装 hook 的检查清单

- 拒绝类判定返回 `hook.Skip(理由)` 而不是 error——前者回传模型自纠，后者终止循环。只有真正该终止的才返回 error。
- 人机交互（审批、提问）用事件 + channel 决策：`state.EmitEvent` 发请求（Data 带 CallID），goroutine 等决策；**同步等在回调里会死锁**。
- 持久化失败记 `state.Metadata["your_error"]` 后返回 nil——写盘故障不应炸掉用户这一轮。
- 钩子里的后台 goroutine 不读写 `LoopState` / `Metadata`，跨 goroutine 只走 channel。
- 静态 system 说明写 `Guide()`，不要在 OnStart 手拼（见 [Hook](Hook.md) 的声明与调整分离）。

## 多租户（Web / 服务端）

ezloop 的并发模型天然适配「一个 Agent 定义、N 个并发会话」：

1. **全局单例 Agent**：构建后只读，所有请求共享；每次 Run 的状态全在独立的 `LoopState` 里。
2. **per-request 事件流**：用 `RunAsync` 的 `Events()` 通道，天然隔离分发。回调式 `WithOnEvent` 是全局共享的，多租户不要用（或只做度量）。
3. **取消传播**：HTTP 断连 → `h.Cancel()`，只取消该请求的循环。
4. **有状态钩子按租户实例化**：持久化这类持状态的钩子 per-tenant 一个；无状态钩子共享。
5. **分身路由**：事件带 ForkID，按它把分身的流式输出、审批请求路由到正确的用户。
6. **工具沙箱**：给文件类工具传 per-tenant 的 root（`fs.NewLocal(租户目录)`），路径越界在底座就被拦住。

## 缓存纪律（KV cache）

前缀缓存命中率的敌人是「同样内容不同顺序」。三条纪律：

- **集合用确定函数定序**：`ToolRegistry.List` 按工具名排序——与注册顺序、resume、重新 New 全无关。自己发明进请求的集合时照此办理。
- **system 全程单条**：基座 + 动态注入 + Guide 声明按注册序追加，`WithHistory` 过滤历史里的 system。多轮不滚雪球。
- **给分身注入说明拼在 input**（请求末尾），不动 seed 前缀；改 system 会从第一条消息分叉，缓存全 miss。

## 错误处理

- 工具错误**回传模型自纠**，不要在工具里吞错或终止循环——模型看到错误才知道换路。
- 持久化类失败记 Metadata 上报，不阻断主流程。
- 消费 `Events()` 时不要假设 `tool_start` / `tool_end` 成对有序到达——以 CallID 关联。

## 测试要求

合入门槛：`go build ./... && go vet ./... && go test ./... -race` 全绿。

- **模型侧行为用脚本驱动**：`internal/testutil.Scripted(...)` 按调用顺序吐 ToolCalls / Text，不 mock 接口以外的任何东西。
- **并发行为必须有 -race 钉子**：并发 Run、并发工具调用各至少一个用例。
- **行为约束落成显式断言**：排序、剥离、隔离这类约束写测试防回归。
- `Guide()` 与无状态的判定逻辑是纯函数，直接断言返回值，不需要装配。
